## 🎯 Overview

Step 2.1.4 raises the project's PHPStan baseline from `level: 5` to `level: 6`. Level 6
is "missing type hints" — every public/protected method, property, parameter, and
iterable value must carry a declared type (or, for genuinely-unknown payloads, an
explicit `mixed`). The migration eliminated **1493 missing-type errors** discovered on
the `develop` HEAD prior to this PR (`app/modules` 936, `app/system` 339,
`app/installer` 102, `app/console` 13, `packages/pagekit` 62) and removed **144
`readonly mixed $` constructor properties** across 41 source files (the 6 occurrences
in `ControllerResolverTest` are the documented test-only exception).

This is a **forward-only** change. Per the No-Mercy / Aggressive rules, no compatibility
layer was added: every parent-class signature change (e.g. `TwigLoader::findTemplate(): ?string`,
`TwigCache::__construct()`, console `execute(): int`, `Logger::__invoke(): void`) is
fixed at the call site, never wrapped. `phpstan-baseline.neon` was *not* regenerated;
every entry that became unmatched as a side effect of the type fixes is **surgically
removed** in the same commit. Wholesale baseline regeneration is explicitly forbidden
for this step.

The migration was executed in **16 sequential checklist steps** (one commit each),
grouped by module risk profile. After all 16 commits a Final-Test mini-loop produced
two additional commits (`style(cs-fixer): …`, `fix(view): …`) folding in regressions
that only `gh run watch` (CI) and Playwright E2E could surface (PHPUnit + PHPStan are
not enough — neither exercises the full HTTP request lifecycle), and a Bugbot
quick-peek mini-loop produced one more commit (`fix: address Bugbot findings …`)
addressing three flagged code-quality issues.

### `readonly mixed $` constructor sweep (144 occurrences across 41 files)

Every `private readonly mixed $foo` constructor parameter (Constructor Property
Promotion artifact left behind by the PSR-11 Stage 3 migration in PR #169) was
replaced with the concrete container-resolved type derived from the corresponding
`index.php` / `ServiceProvider`. Notable examples:

- `MailController` / `RegistrationController` / `ResetPasswordController` —
  `mixed $mailer` → `\Pagekit\Mail\Mailer` (concrete class, not the
  `MailerInterface` plugin interface — controllers call `Mailer::create()` /
  `Mailer::send()`).
- `AuthController`, `ProfileController`, `UserApiController`, etc. — `mixed $auth`
  → `\Pagekit\User\Auth\Auth`, `mixed $request` → `Symfony\Component\HttpFoundation\Request`,
  `mixed $session` → `Pagekit\Session\Session`, etc.
- `PackageController`, `MarketplaceController`, `UpdateController` —
  `mixed $packages` → `Pagekit\Package\PackageManager`, `mixed $modules` →
  `Pagekit\Module\ModuleManager`, etc.
- The 6 `private readonly mixed $` properties in
  `app/modules/kernel/src/Tests/ControllerResolverTest.php` are intentionally
  preserved — they exercise the `ControllerResolver`'s name-based resolution under
  test (resolves by parameter NAME, not TYPE). A class-level docblock documents
  the rationale per Step 2.1.4 §5.1 of the plan.

### Cross-module side-effect fixes (architect amendments)

- **`app/system/modules/site/src/Controller/MenuApiController.php`** (Step 7
  side-effect, architect amendment 2026-05-04): adding the strict `: bool` return
  type to `Mailer::send()` narrowed PHPStan's inference of `__()` at the call site,
  which broke the existing `offsetAccess.notFound` baseline entry. Resolved per
  amendment option (e) using `'count' => max(0, 0)` to defeat literal-`0` narrowing
  while keeping zero behavioural change. Surgical baseline removal of the matching
  entry. Broader Step-9 work on this file (return-type annotations on all action
  methods) was applied normally in Step 9.
- **`app/modules/database/src/ORM/{ModelTrait, PropertyTrait, QueryBuilder}.php` +
  `app/modules/auth/src/Auth.php`** (Step 8 side-effect, architect amendment
  2026-05-04 "scope expansion #2"): typing `User`/`Role` model properties
  concretely caused PHPStan to resolve the ORM traits in those concrete contexts,
  surfacing 11 emergent errors (`static` return types, missing `where()`,
  redundant `isset.property` guards). Resolved by adding `instanceof static`
  guards on `ModelTrait::create()`/`find()`, switching `PropertyTrait` to
  `ReflectionClass::getStaticProperties()` (runtime-modification-safe), adding
  `@method` docblocks to `QueryBuilder` for inherited methods, and narrowing
  `Auth::login()`/`logout()` return types from `EventInterface` to `LoginEvent`/
  `LogoutEvent` to keep `AuthController` happy under L6.
- **`app/system/modules/view/index.php`, `app/system/modules/widget/index.php`,
  `app/system/modules/user/index.php`, `app/system/modules/site/index.php`,
  `app/system/modules/site/widgets/{text,menu}.php`, `packages/pagekit/blog/index.php`**
  (Final-Test mini-loop): the new `array $dependencies = []` strict parameter type

## ⚠️ Breaking Changes for Extensions

Internal-only — public extension APIs are unchanged. The following are
internal-API breaks (per the modernization rules, internal API breakage is
encouraged in Step 2.x):

- `MessageInterface::send(?array &$errors = null): int` and
  `MessageInterface::queue(?array &$errors = null): int` — interface-level
  out-parameter type narrowed from untyped `&$errors` to `?array &$errors = null`.
  Extension-level implementations of `MessageInterface` must update their
  signatures accordingly.
- `Mailer::send(Email $message): bool` — return type added; previously untyped.
  Extensions overriding `Mailer::send()` must declare the matching return type.
- `EventDispatcherInterface::on/off/subscribe/unsubscribe(): self` — return
  type changed from `: void` to `: self` for fluent chaining. Extensions
  implementing the interface must add `return $this;` if they previously had
  void implementations.
- `Auth::login(): LoginEvent` / `Auth::logout(): LogoutEvent` — return type
  narrowed from `EventInterface` to the concrete event classes. Extensions
  consuming the return value via the interface continue to work; extensions
  intercepting via `EventInterface` should narrow their type hints.
- `ModelTrait::create()` / `ModelTrait::find()` now throw `\LogicException`
  if the resolved instance is not `instanceof static`. This was always the
  intended contract; the throw makes the contract explicit.
- `PropertyTrait::getProperties()` / `getPropertyDescriptor()` now use
  `ReflectionClass::getStaticProperties()` instead of direct `static::$properties`
  access. Behaviour is identical for any class that defines `$properties` at
  declaration time (Pagekit's universal pattern), but extensions that mutate
  `static::$properties` via reflection at runtime now correctly observe those
  changes (previous default-only behaviour was a latent bug).
