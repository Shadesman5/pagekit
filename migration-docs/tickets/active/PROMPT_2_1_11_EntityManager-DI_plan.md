- **Architecture decisions (constraints from prompt §2 all hold):**
  1. **Generic `Repository<T>`** (`Pagekit\Database\ORM\Repository`, non-final, `@template T of object`): ctor `(protected readonly EntityManager $em, protected readonly Metadata $metadata)`; methods `query(): QueryBuilder<T>`, `where(mixed $condition, array $params = []): QueryBuilder<T>`, `find(int|string $id): ?T`, `findAll(): array<int|string, T>`, `create(array $data = []): T` (via `$em->load()`), `save(object $entity, array $data = []): void`, `delete(object $entity): void`, `removeRole(int $roleId): int` (ports `AccessModelTrait::removeRole` SQL via metadata table + connection; **int only** — the database module must not import `Pagekit\User\Model\Role`; guard: `\LogicException` when the metadata has no `roles` field). `EntityManager::getRepository(class-string<T>): Repository<T>` with **per-EM instance map** (no statics). `EntityManager::find()` re-implemented as `$this->getRepository($entity)->find($identifier)` — the `"{$entity}::find"` string-callable delegation is deleted.
  2. **Custom repositories as container services** (composition root builds them; the EM only ever creates generic ones): `NodeRepository` (site — cached finders + `fixOrphanedNodes`), `UserRepository` (user — `findByUsername`/`findByEmail`/`findByCredentials`/`updateLogin`/`findRoles`), `PostRepository` (blog — `updateCommentInfo`/`getAuthors`). Plain entities get generic services. **Service names = controller constructor param names** (ControllerResolver injects BY PARAM NAME — 2.1.10 precedent `nodePresenter`): `nodeRepository`, `pageRepository`, `userRepository`, `roleRepository`, `widgetRepository`, `postRepository`, `commentRepository`. Registration: site/user in `Module::main()`, widget in its `index.php` `main`, blog in its `boot` closure (postPresenter precedent). All factories resolve `$app->get('db.em')` lazily — **`db.em` remains the sole registration** (prompt requirement), no `em` alias, no top-level EM service.
  3. **Lifecycle handlers keep their attribute-registered static shape but lose all global state:** new `EntityEvent extends Pagekit\Event\Event` carrying the emitting `EntityManager` (`getEntityManager()`); `EntityManager::trigger()` dispatches `new EntityEvent("{prefix}.{name}", $this)` through the existing `db.events` PrefixEventDispatcher (external `model.*` subscribers keep working — they type `EventInterface`). Handlers change signature to `(EntityEvent $event, X $entity)` and reach queries via `$event->getEntityManager()->getRepository(...)` / `->getConnection()`.
  4. **`toArray()`/`jsonSerialize()` stay on entities (raw-entity controller returns depend on them) but metadata access becomes injected data, not a live object:** new `Metadata::getSerializationMap(): array{relations: list<string>, fieldTypes: array<string, string>}` (lazy, plain arrays); `EntityManager::load()` injects it into entities implementing new `SerializableModelInterface` (`setSerializationMap()`, provided by `ModelTrait`; all 8 entities add `implements`). **Deliberately NOT a live `Metadata` reference:** a `Metadata` instance holds `MetadataManager → Connection` — storing it per-entity would make every future entity serialization (PSR-6 query cache, `serialize()`) explode; plain arrays are serialization-safe. `toArray()` reads the map (`\LogicException` with instructive message when absent, i.e. manually `new`-ed entities — verified: the only production raw-`new` is `MenuHelper`'s root placeholder `new Node(...)`, which never serializes) and additionally **skips `_`-prefixed properties and `\Closure` values** (protects `$_serializationMap` + the new role loader from leaking into JSON).
  5. **Central hydration type-guard replaces the ~10 per-call-site `instanceof` LogicException guards:** `EntityManager::load()` asserts the created instance against `$metadata->getClass()`. With `Repository<T>`/`QueryBuilder<T>` typed results, the per-site guards become PHPStan-dead (`instanceof` always-true) and are deleted at each migration step; the runtime protection (pinned by mutation tests) moves to the one choke point that covers `first()`, `get()`, `related()` and `create()`.
  6. **`User::hasPermission()` roles lookup (security-critical, called on the current-user instance everywhere):** `UserModelTrait` gains `#[ORM\Init]` handler `init(EntityEvent $event, User $user)` that attaches a **per-instance role-loader closure** (`fn (list<int|string> $ids): array<int|string, Role>` via `$em->getRepository(Role::class)->query()->whereIn('id', $ids)->get()`; empty-ids guard returns `[]`) through new `User::setRoleLoader(\Closure)`. `hasPermission()` keeps its per-instance `$permissions` memo, uses the loader, throws `\LogicException` when no loader is attached (un-hydrated `new User()`). Every production `User` flows through `EntityManager::load()` (auth provider find, anonymous `create()`, admin CRUD) → loader always attached. The cross-user `static $cached` role cache in `findRoles` is **deleted** (premature optimization, roles table is tiny; Step 4.3 owns perf). `UserRepository::findRoles(User): array` remains for the debug collector. This is what makes `hasPermission()` unit-testable with an injected fake loader (prompt §3, `UserTest` deferred note resolved).
  7. **Node request cache (RC-2):** cached `find`/`findAll`/`findByMenu` move from `NodeModelTrait` statics into `NodeRepository` backed by an injected `CacheItemPoolInterface`. Composition root wires `new ArrayAdapter(0, false)` — **`storeSerialized: false` is mandatory** (preserves the current shared-instance semantics of the static cache — `NodesListener`/`MenuHelper`/`node` service mutate the same objects — and avoids serializing entities). Cached semantics ported 1:1 (memoized full set on `findAll(true)`, per-id memo on `find($id, true)`, no invalidation on save — invalidation strategy is Step 4.3).
  8. **`PositionHelper` function-statics `$widgets`/`$positions`** become instance properties (same global-mutable-state class as the singleton; helper is per-request).
