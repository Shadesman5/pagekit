- **Decisions (Refactorer MUST heed — the plan decides these, not the step):**
  1. **The refusal list — `PackageArchive::open(string $file): self` throws `ArchiveRefusedException` (message via `__()`, naming the reason) and writes nothing.** In this order:
     (a) not a readable ZIP with at least one entry;
     (b) any entry name that, with `\` refused outright, is empty, contains a NUL byte, starts with `/`, matches `^[A-Za-z]:`, or has a `.` or `..` segment; any entry whose external attributes mark it a symlink (unix mode `S_IFLNK`); a total declared uncompressed size above `PackageArchive::MAX_UNCOMPRESSED_BYTES` (512 MiB);
     (c) no root-level `composer.json`, or one that is not a JSON object; missing/invalid `name` (`PackageArchive::NAME_PATTERN` = `^[a-z0-9][a-z0-9_.-]*/[a-z0-9][a-z0-9_.-]*\z`), `type` not in `{pagekit-extension, pagekit-theme}`, missing/invalid `version` (`PackageArchive::VERSION_PATTERN` = `^[A-Za-z0-9][A-Za-z0-9._-]*\z` — the snapshot store's id alphabet; a `+build` suffix is refused and the message says so), missing/empty `title`; `extra.scripts` set but naming no entry in the archive;
     (d) no root-level `index.php`; one `nikic/php-parser` cannot parse; no top-level `return` of an array literal; no `'name'` string literal, or one that is not `basename(composer name)`; no `'autoload'` key, or one that is not an array literal of string-literal keys and values (`[]` is valid and means "nothing to autoload"); an `autoload` value naming a directory the archive does not contain.
     A wrapping top-level directory (GitHub-style zips) fails (c) — the contract is root-level files. Validation reads the manifest without executing it: the archive is untrusted until (d) passes, and 2.7.3 retargets one reader. Everything in (c)/(d) is one private static method (`PackageArchive::manifest()` for the PHP half); no second class.
  2. **Page type is the caller's check.** `uploadAction(string $type)` refuses `$archive->type() !== 'pagekit-' . $type` with `BadRequestHttpException` (as today); `php pagekit install` takes any of the two types.
  3. **Target and update semantics — in `PackageManager::install()`.** Target is `<path.packages>/<vendor>/<name>` from the validated composer name; `path.packages` is read from the container with no fallback (all three boots set it in `public/index.php`). Refused with `\RuntimeException` before anything is written: the factory knows the name at a different path; the factory knows the name with a different `type`; the target exists as a link. Target exists as a directory → update: `$previous = $factory->get($name, true)` and `$moduleLoaded = $previous !== null && $this->app->get('module')->get($previous->get('module')) !== null` are read **before** the tree moves; after `replaceTree()` and `$package = $factory->get($name, true)` (null → `\RuntimeException`), `$moduleLoaded ? $this->enable($package, $previous) : $this->doInstall($package)` — exactly today's branch, migrations run from the recorded version. A disabled package re-uploaded takes the `doInstall()` branch, as today.
  4. **One method replaces the tree.** `private function replaceTree(PackageArchive $archive, string $target): void`: `makeDir(dirname($target))`; extract into a hidden sibling `dirname($target) . '/.' . basename($target) . '-' . bin2hex(random_bytes(4))` (a sibling because `rename()` is atomic only on one filesystem, hidden because `glob('*')` in `PackageFactory::loadPackages()` and `ModuleManager::register()` skips dot-names, so no request sees a half-written package); if the target exists `rename($target, <hidden retired sibling>)`, then `rename($staged, $target)` — a failed second rename puts the retired tree back and throws; delete the retired tree through the `file` service, and a retired tree that will not delete is a line on `$this->output` and in the log, not a failed install (it is invisible to the factory); on any failure the staged tree is deleted and the exception rethrown. After the swap, `opcache_invalidate($file, true)` for every `.php` under the target when the function exists — the lifecycle runs in the same request and must not compile the replaced files from cache. Windows `glob()` may list dot-directories; that is a 2.7.3 concern (static registration), not a reason for a second staging location. Nothing of this leaks into the controller: 2.9 puts its snapshot in front of this one method.
  5. **Extraction.** `PackageArchive::extractTo(string $directory): void` runs only on an instance `open()` produced (an instance is the proof of validity). Entry-by-entry via streams or `ZipArchive::extractTo()` after the full validation — either; file and directory modes come from the umask, never from the archive; IO failure is `\RuntimeException`.
  6. **Staging.** `PackageModule::main()`: `$app->set('packageStaging', fn ($app) => $app->get('path.temp') . '/packages');` — the same injection-by-name mechanism `systemApi` used (`ControllerResolver::instantiateController()` resolves constructor parameters by container id, so a dotted id cannot be injected directly). The constructor's `string $path` becomes `string $packageStaging` at the same position (the container fills parameters by name; the three existing test constructions — `PackageHookWarningTest:359`, `PackageFailureRecordTest:784`, `RemovalPromiseTest:205` — pass a workspace string there and keep compiling). `uploadAction()`: `PackageArchive::open($file->getPathname())` on the PHP upload temp (nothing written on refusal — PHP discards the temp); an `ArchiveRefusedException` is rethrown as `BadRequestHttpException($e->getMessage(), $e)` — the page reads the reason out of a 400 body (`package-upload.vue` `onComplete`), a bare `RuntimeException` would reach it as a 500 without one; then the page-type check (decision 2, `BadRequestHttpException`, before the move — a wrong-type archive is never staged); then `$file->move($this->packageStaging, "<vendor>-<name>-<version>.zip")` (`UploadedFile::move()` creates the directory); returns `['package' => …]` built from `$archive->composer()` through `PackageFactory::load()` with `extra.icon`/`extra.image` stripped as today and no `shasum`. `installAction(array $package = [])` (`RequestAttribute(['package' => 'array'], csrf: true)`, GET stays) reads only `name` and `version`, checks both against the two patterns (a missing key fails the check) — anything else in the array is ignored, the target is derived from the archive's own manifest in `PackageManager::install()`, never from the request; opens `<packageStaging>/<vendor>-<name>-<version>.zip` with `PackageArchive::open()` (re-validation is the boundary: the file sat on disk between requests; a missing file and a refused file are both `status=error` with the reason on the stream, and `install()` is not called); streams `$this->manager->install($archive)`; deletes whatever sits at the staged path in `finally` — success, refusal or failure alike (a delete that fails is logged, not streamed); calls `$this->clearCache()` after success, and ends with `status=success`/`status=error`. Failure policy mirrors `uninstallAction()`: an `\Exception` message is streamed as it stands, an `\Error` is logged and a generic line is streamed — generalise `removalFailure()` (rename at refactorer's discretion) rather than duplicate it. `CacheModule::clearCache()` empties `path.temp` at depth 0, staging included — a staged file that is gone at install time is a refusal, not something to protect.

  8. **`ArchiveCommand` on `\ZipArchive` + Finder + the runtime's own gitignore compiler — same output, one library less.** Validate `name` against `PackageArchive::NAME_PATTERN` before it touches a path (the traversal PHASE 5 §5.6 names); source `<path.packages>/<name>` must be a directory; output `<dir>/<vendor>-<name>.zip` (`strtr($name, '/', '-')` — `getPackageFilename()` goes, a validated name needs no sanitising); files only, forward-slash relative paths; Finder `files()->ignoreDotFiles(false)->ignoreVCS(true)`. The rules are the package's root `.gitignore` lines (comments and blanks skipped) followed by `composer.json` `archive.exclude`, in that order. **Each rule is compiled by `Symfony\Component\Finder\Gitignore::toRegex()`** (`symfony/finder` 6.4 is in `require`): the command strips a leading `!` and keeps it as the rule's negation flag, then calls `Gitignore::toRegex($rule)` with **that one rule** — the result is the anchored regex for "the rule's target or anything below it" in the full gitignore grammar (leading `/` anchors at the package root, no `/` → any depth, `*`/`?` within one segment, `**` across segments, a trailing `/` matches only what lies below, `[...]` classes). **The only private code in `ArchiveCommand` is the loop:** for a file's relative path, test every compiled rule in order; the last one that matches decides (negated → keep, otherwise → drop); no rule matches → keep. No class under `app/`, no regex writing, no Finder `notPath()` translation. **Why one call per rule and never `toRegex(<whole file>)`:** the library's whole-file mode implements git's hierarchical negation — a `!` rule becomes a whole-string-anchored negative lookahead, so `!/app` re-includes the path `app` itself and nothing below it — while the shipped `archive.exclude` rules were written for Composer's flat model, in which `!/app` re-includes everything under `app/`; per-rule compilation keeps the flat model with the library's grammar. **The model is flat, not git's hierarchical walk:** every rule is tested against the file's whole relative path, a rule matches when that path is the rule's target or lies below it, the last matching rule decides, and there is no "an excluded parent cannot be re-included" clause. On the shipped trees that reads: `theme-one` (`/app/assets/*`, `/node_modules`, `.DS_Store`, `.idea`, `*.zip` from `.gitignore`; `node_modules`, `!/app`, `!/css`, `/app/assets` from `archive.exclude`) keeps everything under `app/` except `app/assets/**` and keeps no `node_modules/`; the blog's `**/app/bundle/**/*.js` matches nothing in a source tree (bundles live under `public/`); neither tracked tree has a file any rule drops, so an archive of either extracts to the tracked tree byte for byte. `composer.json` read with `json_decode(..., JSON_THROW_ON_ERROR)`; `archive.scripts` is **not** executed — the `system()` hook is deleted (a package-supplied shell command run by a core command; 2.8 owns author tooling). ### Step 1
- `PackageArchive::entries()` — beyond 1(b): two entries equal after dropping the trailing `/` and ASCII lower-casing refuse ("more than once"), and so does a file that is another entry's folder ("both as a file and as a folder") — the manifest read takes the first match while extraction writes every entry, case-insensitive filesystems included. Empty segments (`a//b`) refuse instead of collapsing. The backslash check runs first, so `C:\win.php` refuses on the backslash (the drive branch needs `C:/win.php`); the symlink check reads `attributes >> 16` whatever the host byte. Invariant: `index.php` twice, `Index.php` + `index.php`, `a` + `a/b` → refused, nothing written.
- `PackageArchive::open()` — a missing, 0-byte or non-ZIP file → "not a readable ZIP archive"; an entry-less archive → "The archive is empty." (`ZipArchive` writes no file without entries — that fixture is the 22-byte end record `"PK\x05\x06" . str_repeat("\0", 18)`).
- `PackageArchive::read()` — `composer.json`/`index.php` declared above 1 MiB (`MANIFEST_MAX_BYTES`) refuse ("is too large"): both are read into memory whole, which the 512 MiB total does not bound.
- `PackageArchive::extractTo()` — streams entry by entry; rejected `ZipArchive::extractTo()`, which overwrites existing paths and cannot hold a file to its listing. Re-opens the file (no handle kept after `open()`) and throws if the count or any index's name/size/CRC changed; `fopen('xb')`, so an existing path fails; never writes past the declared size and checks size + CRC itself ("is damaged"), because PHP's zip stream reports an end-of-entry CRC error as plain EOF; modes `0666`/`0777` under the umask. A failure leaves what was written — cleanup is `replaceTree()`'s — so a test asserts the exception, not an empty directory.
- `PackageArchive::manifest()` — the manifest is the file's only `return` outside function and class bodies (closure, method and anonymous-class returns do not count): a second one refuses, because a condition or a `goto` picks which one PHP takes; that one must be top-level, under `namespace X;` too (whether the node holds the code after it, as `parse()` yields, or has null `stmts` with that code as siblings) — one only inside `if`/`declare`/`try` refuses. Keys resolve last-wins, and a spread or a computed (non-string, non-integer-literal) key clears the literal keys before it: `['name' => 'blog', 'autoload' => [], $k => 1]` and `[…, ...$x]` refuse, `[$k => 1, 'name' => 'blog', 'autoload' => []]` passes. Every `autoload` item is folder-checked, an overridden duplicate too. Invariant: each (d) refusal is an `ArchiveRefusedException`, never an `Error`/`TypeError`.
- `PackageArchive::relative()` — `extra.scripts` and `autoload` values drop empty and `.` segments; `''`, a leading `/`, a drive prefix or any `..` refuses; autoload `.` is the package root. Autoload values get `\` → `/` first (as `AutoLoader` does), scripts do not. Scripts count only when non-empty (the runner's `!$scripts`); a non-string value refuses.
- `PackageArchive::printable()` — archive-supplied strings quoted in a message get control characters and invalid UTF-8 replaced by `?`.
- Safety gates — branch contains `origin/develop`, `composer install` a no-op, `pnpm install --frozen-lockfile && pnpm build` exit 0 before any edit; the PHPUnit/PHPStan baseline is left to the Tester (the refactorer runs no suite).
