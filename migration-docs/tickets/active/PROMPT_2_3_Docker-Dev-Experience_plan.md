- **⚠️ Architect decisions + verified discovery (Refactorer MUST heed):**
  1. **Bundled-extension baseline (assumption — no Docker daemon in-agent):** official `php:8.5-apache` / `php:8.5-cli` Debian images bundle `pdo`, `pdo_sqlite`, `sqlite3`, `mbstring`, `xml`, `dom`, `xmlwriter`, `simplexml` (among others) and do **not** bundle `pdo_mysql`, `gd`, `zip`, `exif`, `pcntl`, `bcmath`. Capability set = `pdo_mysql`, `pdo_sqlite`, `mbstring`, `gd`, `zip` (+ PCOV agent-image-only) ⇒ the only `docker-php-ext-install` entries in **both** Dockerfiles are **`pdo_mysql`, `gd`, `zip`**. `exif`/`bcmath`/`pcntl`: zero usage outside `app/vendor/` (verified: no `exif_*`/`bc*`/`pcntl_*` calls; `composer.json` `ext-*` = dom, json, libxml, mbstring, xml, xmlwriter, zip, simplexml, pdo — all satisfied by bundled + `zip`). `php -m` confirmation of the bundled list = Manual Work.
  2. **Baking decision — the dev image stops baking app code.** Delete `COPY . /var/www/html`, `composer install --no-dev --optimize-autoloader`, and the `chown -R`/`chmod -R` layers from the root `Dockerfile`. Rationale: the dev compose bind-mounts `.:/var/www/html` over the baked code (it is invisible in the documented flow), README documents in-container `docker compose exec web composer install`, and production baking is Step 2.5. The image reduces to: PHP 8.5 + Apache (mod_rewrite + vhost) + extensions + Composer binary. `.dockerignore` still matters (context-transfer size + Step 2.5 reuse).
  3. **`check-version-ssot.php` parses `^FROM php:` from BOTH Dockerfiles** — keep `FROM php:8.5-apache` / `FROM php:8.5-cli` lines intact (only extension/apt/layer content changes). Run the script after touching the Dockerfiles.
  4. **Profile mechanism — delete `profiles:` outright.** Default path: bare `docker compose up` starts web + mysql + phpmyadmin + node (no `default` profile magic — Compose never auto-activates a profile named `default`; the current file's MySQL never starts on bare `up` while `web` still depends on it). SQLite zero-DB path: **`docker compose up -d --no-deps web node`** (`--no-deps` skips the `depends_on` MySQL pull-in; app is installed with `docker compose exec web php pagekit setup … -d sqlite`). No override files, no `COMPOSE_PROFILES`, no phantom `sqlite` profile.
  5. **Env mechanism — Compose-native `.env`.** `environment: ${VAR}` interpolation reads shell + project `.env` only, never `env_file:` — the current wiring resolves to empty strings on a clean shell. Fix: setup scripts generate **`.env`** (rename `docker.env.example` → `.env.example`); compose maps vars via interpolation; **delete all `env_file:` entries**. Minimal var set: `MYSQL_DATABASE`, `MYSQL_USER`, `MYSQL_PASSWORD`, `MYSQL_ROOT_PASSWORD`. Verified consumers: mysql image bootstrap + phpmyadmin only — the PHP app reads **no** env vars (no `getenv`/`$_ENV` consumers in `app/`), so the `web` service gets no env at all; `APACHE_DOCUMENT_ROOT` is dead (custom vhost hardcodes the path) — drop. `APP_URL`, `PHPMYADMIN_URL`, `PHP_MEMORY_LIMIT`, `PHP_UPLOAD_MAX_FILESIZE`, `PHP_POST_MAX_SIZE`, `APP_ENV`, `APP_DEBUG`, `DB_HOST`, `DB_PORT` have no consumers (php.ini hardcodes its values; phpmyadmin host/port become literals) — drop. Gitignore: `*.env` (line 52) covers `.env` — verified via `git check-ignore`; drop the now-redundant explicit `docker.env` line.
  6. **MySQL 8.4 + healthcheck:** drop `command: --default-authentication-plugin=mysql_native_password` (server option removed in MySQL 8.4 — refuses to start on a cold volume; PHP 8.5 mysqlnd speaks `caching_sha2_password` natively). Healthcheck must probe **TCP, not the socket** — during first-boot init the entrypoint's temporary server is socket-only (`skip-networking`), so `-h localhost` reports healthy too early: `test: ["CMD", "mysqladmin", "ping", "-h", "127.0.0.1", "--silent"]` + `interval`/`timeout`/`retries` + `start_period`. Gate `web` AND `phpmyadmin` with `depends_on: { mysql: { condition: service_healthy } }`.
