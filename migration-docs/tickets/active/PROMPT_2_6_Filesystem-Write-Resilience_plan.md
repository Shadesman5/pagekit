- **⚠️ Architect decisions + verified discovery (Refactorer MUST heed):**
  1. **Home & API (the one real decision):** the primitive is `Filesystem::dumpAtomic(string $file, string $content, ?int $mode = null): void` on the existing `Filesystem` class (service id `file`). No new class, no new service id, no static state — the `file` service stays the single filesystem glue point, and the name matches PHASE_2 §2.6. Throws `\RuntimeException` on total write failure; never returns `false`. Method contract documents the honest atomicity limit: `rename()` is atomic only within one filesystem (temp file is created in the **target directory** for exactly that reason), and the Windows-lock fallback is a plain `LOCK_EX` write, not atomic.
  2. **Dependency direction (verified):** `Router` gains a trailing constructor parameter `Filesystem $files = new Filesystem()` (new-in-initializer; injectable for tests, zero churn for the 4-arg constructions in `app/modules/routing/index.php` and `RouterTest`). Do **not** add `filesystem` to routing's module `require` and do **not** reach for `$app->get('file')` in the router factory — the manifest declares service/boot dependencies, and a plain class import needs none (the tree's own precedent: `Filesystem.php` imports `Pagekit\Routing\Generator\UrlGenerator` for constants while the filesystem module requires nothing). Composer PSR-4 maps `Pagekit\Filesystem\` → `app/modules/filesystem/src`, so the class loads in every environment regardless of module state. A fresh adapter-less instance is correct here: the cache path is always a plain local path.
  3. **Algorithm (extracted 1:1 from `Router::writeCache()`, plus opcache):** `tempnam(dirname($target), ...)` → write content to temp → chmod (decision 4) → `rename()` over target; if the rename is blocked (Windows reader locks), remove the temp file and fall back to a direct `file_put_contents($target, $content, LOCK_EX)`; remove the temp file on **every** failure path (assert no residue in tests); throw `\RuntimeException` when the fallback also fails. After a successful write (either path): `if (function_exists('opcache_invalidate')) { opcache_invalidate($target, true); }` — all three targets are PHP files read back via `require`, so invalidation lives in the primitive, not in callers.
  4. **Permissions (stated decision — no silent loosening):** when the target file already exists, carry its current permission bits over to the replacement (`fileperms($target) & 0777` applied to the temp file before rename) — today's `file_put_contents` rewrite preserves the existing mode, and a rename would otherwise reset an operator-hardened `config.php` (e.g. 0600) back to 0644. When creating fresh, apply `($mode ?? 0666) & ~umask()` — byte-for-byte parity with today's `file_put_contents` create semantics and with the router's existing chmod. `$mode` stays an optional parameter; no current caller needs to pass it.
  5. **Protocol safety (fail loudly):** resolve the target via `getPathInfo()`; require protocol `file` and a non-empty local `pathname`, otherwise throw (`\InvalidArgumentException`). Never degrade an adapter-backed/stream protocol to a non-atomic write.
  6. **SettingsController wiring (verified):** `ControllerResolver::instantiateController()` resolves constructor parameters **by parameter name** against container service ids (`app/modules/kernel/src/Controller/ControllerResolver.php:196-211`). Add `private readonly Filesystem $file` — param name `file` = service id `file`; no `index.php` change needed. `saveAction()` calls `$this->file->dumpAtomic($file, $fileConfig->dump())` and drops its own `opcache_invalidate` block (now central — no double invalidation). A failed write now throws instead of returning `['message' => 'success']` — that is the fix for the ignored return value; let the exception propagate (500 to the admin UI, not a fake success).
  7. **Installer (verified reachable):** `installer` module requires `application`, which requires `filesystem`, so the `file` service exists during install (`app/installer/app.php` boot chain). Replace the `if (!file_put_contents(...))` block with a `try/catch (\RuntimeException)` around `$this->app->get('file')->dumpAtomic($this->configFile, $configuration->dump())` that sets `$status = 'write-failed'` and rethrows as `BadRequestHttpException(__('Can't write config.'))` — the existing user-visible failure contract must survive unchanged.
  8. **Composer helper (no service locator inside):** constructor becomes `__construct(array $config, ?OutputInterface $output = null, ?Filesystem $files = null, ?LoggerInterface $logger = null)` with `$files ??= new Filesystem()` and `$logger ??= new NullLogger()` (`psr/log` is a direct dependency). `writeConfig()` goes through `$this->files->dumpAtomic($this->file, '<?php return ' . var_export($this->packages, true) . ';')` — the registry is read back via `require` in `readConfig()`, so the centralized opcache invalidation matters here too. `PackageManager` (the only live construction site; the two `new Composer(...)` occurrences in console commands are commented out and stay untouched) passes `$this->app->has('file') ? $this->app->get('file') : null` and `$this->app->has('log') ? $this->app->get('log') : null`.
  9. **Invalid version constraint — log, do NOT skip (behaviour preserved, decision recorded):** `VersionParser::normalize()` rejects perfectly valid *range* constraints (`^1.0`, `~2.3`) because it parses exact versions — the catch is hit by legitimate installs, and skipping the package would break them. The force-refresh is only meaningful for exact versions, so the correct semantics are: log at **info** level naming package and constraint (e.g. "Version constraint for <package> is not an exact version (<constraint>); skipping forced refresh.") and continue exactly as today. No behaviour change → nothing extra for the branch doc beyond the decision itself; the test pins both the log record and the package still landing in the registry.
  10. **SelfupdateCommand cleanup (Rule 4):** delete the commented-out block (former body, lines 45-85) and the now-unused `use Pagekit\Installer\SelfUpdater;` import. Keep: the Step 5.6 TODO marker, the `error()` + `Command::FAILURE` behaviour, `getVersions()`, `download()`. Git history is the reference — no archived copy anywhere.
  11. **Untouched by design:** cache freshness (`filemtime` comparison in `getCache()`), the dumpers, and `getMatcher()`/`getGenerator()` graceful degradation — `RouterTest::testCorruptCacheFileFallsBackInsteadOfFatal` (`app/modules/routing/src/Tests/RouterTest.php:238`; the task prompt's name for it is stale) must pass **unmodified**. The router tolerates a corrupt cache by design; the config writers must not inherit that tolerance — they throw.
  12. **PHPStan:** baseline has 6 entries for `Composer.php` (matched by message, unaffected by the signature change) and none for `Filesystem.php`/`Router.php`/`SettingsController.php`. No new baseline entries; suppress nothing.
