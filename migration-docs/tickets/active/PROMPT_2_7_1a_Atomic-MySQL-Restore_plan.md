- **⚠️ Architect decisions + verified discovery (Refactorer MUST heed):**
  1. **Prefix invariant home (Discovery Q1).** One validator, `TablePrefix` in `app/installer/src/` (wizard-side — it stays in `installer` when 2.7.1b moves the package machinery out). Enforcement point is `Installer::check()` under `!$this->config`, which both entries flow through (web installer posts to it; `SetupCommand` calls `install()` → `check()`), so the CLI refusal of `--db-prefix=` is the same code path surfaced by the existing error handling — one rule, zero drift. `EnvConfigLoader` deliberately does **not** consume the validator: its only change is blank-reads-as-unset, because a boot that dies on an ill-shaped overlay would break the "existing installations keep booting" promise. The shape's leading-letter requirement is what keeps the reserved `_r_`/`_b_` namespace uninstallable — no separate reserved-prefix list in the validator, but its docblock says why the leading letter is load-bearing.
  2. **Reserved names + ownership.** Constants for the `_r_` (shadow) and `_b_` (backup) markers live in one small class in `Snapshot/`, consumed by dumper (skip in `schema()`), restorer (naming, cleanup, refusals) and tests. Equal length, outside any legal install prefix. A reserved-marker table whose remainder starts with this installation's prefix is **owned** by this restorer (safe to drop at cleanup); any other collision with a needed `_r_`/`_b_` name is a refusal. Ownership matching and collision checks both follow the server's `lower_case_table_names` folding (read the variable; fold both sides when it says the server does) — never PHP's default case sensitivity (Discovery Q6).
  3. **Refusal wording (Discovery Q2).** Empty-prefix MySQL restore is refused in `restore()` before the dump is even opened (cheapest refusal; `inspect()` covers dump-shape refusals, this one is about the installation). The message must name the fact and the action, e.g.: "This installation's tables have no name prefix, so a restore cannot tell them apart from the rest of the database while it swaps them. Reinstall with a table prefix (the default is pk_) to make restores possible." — final copy is the Refactorer's, but it is operator-facing (it reaches the panel via the existing `SnapshotController::failed()` path) and must never be a platform lecture.
  4. **Constraint renaming (Discovery Q3).** MySQL 8 foreign-key and CHECK constraint names are schema-unique and capped at 64 chars. Regenerate every one in shadow DDL as a short token (e.g. `_r_` + hex from hash of table + original name, well under 64) — never prefix the dump's names (overflow + collision with live). Regenerated names cannot collide with live names, and when live tables become `_b_` they keep their original constraint names (RENAME TABLE does not rename constraints), so no collision appears at cut-over either. Index names are per-table in MySQL — inside a freshly created shadow table no collision is possible, so index names are **never** rewritten. Consequence to document (README note): constraint names on a MySQL-restored installation are regenerated tokens; MySQL has no RENAME CONSTRAINT, so they stay.
  5. **Shadow DDL derivation (Discovery Q4) — the corruption risk centre.** Shadow DDL is the dump's DDL with table identifiers and `REFERENCES` targets rewritten and constraint names regenerated. Never `CREATE TABLE … LIKE` live tables (live schema may have migrated since the snapshot). Verified: the dump's DDL comes from DBAL `getCreateTableSQL(...)` on `AbstractMySQLPlatform` and may contain **unquoted** identifiers and multiple statements per table (`CREATE TABLE`, `ALTER TABLE … ADD CONSTRAINT … REFERENCES`, `CREATE [UNIQUE] INDEX … ON`). The rewriter must therefore tokenize: honour backtick-quoted identifiers and `'…'` string literals (a `DEFAULT 'pk_users'` literal is data, never rewritten — this is the "column value contains a table name" test the prompt demands), and rewrite identifier tokens only in grammar positions (`CREATE TABLE <t>`, `ALTER TABLE <t>`, `REFERENCES <t>`, `CONSTRAINT <c>`). Rewritten output always emits backtick-quoted identifiers. `REFERENCES` targets are rewritten **only** for tables the dump names; an outbound FK to a table outside the dump keeps pointing at the live table. Row data is never rewritten at all — inserts go through the prepared `INSERT INTO <quoted shadow name>` with bound values, which is why values cannot be corrupted. A `str_replace` over DDL text is a rejected design, not a shortcut.
  6. **Connection placeholder trap.** `Connection::replacePrefix()` substitutes `@name` outside quoted strings on **every** `prepare`/`executeQuery`/`executeStatement`. All shadow SQL uses literal quoted identifiers (backticks) and never a `@`-placeholder spelling like `@_r_users`; `GET_LOCK('literal', …)` arguments are quoted strings and safe.
  7. **Preflight refusals (the feature).** All MySQL refusals run after `inspect()` has read the whole dump and before the first `CREATE`, while the installation is untouched: (a) empty prefix (decision 3, before the dump is opened); (b) a rewritten table name over 64 chars (`_r_`/`_b_` add 3 chars, so live names over 61 refuse; regenerated constraint tokens are short by construction, but the check stays general); (c) a needed shadow/backup name colliding with an existing non-owned table (folding per decision 2); (d) inbound FKs — any table **not** in the dump referencing a dumped table (`information_schema.REFERENTIAL_CONSTRAINTS` + `KEY_COLUMN_USAGE`, current schema, folding-aware), because InnoDB would remap that FK onto the `_b_` name at rename and the backup drop then fails or a neighbour hangs; the message names the offending tables/constraints; (e) owned leftovers that will not drop (Step 6 turns presence-refusal into drop-then-refuse-on-failure, after the lock is held); (f) a dump that names a reserved `_r_`/`_b_` table (both platforms — never legitimate, and unguarded it would create `_r__r_…`).
  8. **Fill and cut-over.** Fill: create shadow tables and insert rows in dump order under the existing `FOREIGN_KEY_CHECKS = 0` window (FKs among shadows may point at not-yet-created shadows; MySQL accepts that with checks off). Any fill failure drops all shadow tables in `finally` — disk-full and timeouts may not leave undeclared `_r_` names. Cut-over: **one** `RENAME TABLE` statement listing every dumped table — live → `_b_` and `_r_` → live; a dumped table with no live counterpart contributes only `_r_` → live; live tables outside the dump are untouched. MySQL executes a multi-pair RENAME atomically; splitting it lets InnoDB remap FKs among the dumped group onto backup names — if the plan or the code splits it, the plan/code is wrong. Lock-wait or `max_allowed_packet` failure on that statement is a failure **before** cut-over: drop shadows, live tables intact. After a successful rename, drop the `_b_` tables (still inside the FK-checks-off window); a failed backup drop is a logged warning on a **successful** restore — the site is already restored, and the next restore's leftover cleanup clears the names.
  9. **One MySQL path.** Step 5 deletes the MySQL reach into `apply()`/`recreate()` in the same commit that wires the shadow path in. `recreate()` and `apply()` themselves **stay** — they are the SQLite transactional apply, which already keeps the promise and is not unified into any new abstraction. `replace()` ends up: SQLite → transaction + `apply()` (unchanged); MySQL → preflight + shadow fill + cut-over; anything else already throws in `DumpFormat::platform()`.
  10. **Serialization (Discovery Q5).** MySQL `GET_LOCK` taken on the restore's own connection before leftover cleanup and held across preflight, fill, cut-over and backup drop; `RELEASE_LOCK` in `finally` (server also releases on disconnect). Lock name ≤ 64 chars, scoped to installation, e.g. `pagekit.restore.` + short hash of schema name + prefix — server-wide names must not collide across installations sharing a server. Timeout 0 (or a small constant): a second concurrent restore is **refused** with "another restore is already running", not queued — Vue `busy` is UI state, not a lock. Leftover cleanup runs strictly after the lock is held, so one restore can never drop another's in-flight shadows.
  11. **Existing installations keep working.** The mysql module default flip cannot strand an installed site: the installer writes `prefix` into `config.php` (`persistableDatabaseConfig()` fills it from resolved config when the form omits it), so installed sites carry their own value; a hand-written `config.php` that omits `prefix` relying on the implicit `''` is the one edge the default flip moves — acceptable per PHASE ("MySQL module default becomes pk_"), noted in the branch doc. An installation with an explicit empty prefix boots, dumps (with the reserved-name skip) and uninstalls exactly as before; only MySQL **restore** refuses it, with the decision-3 message. SQLite restore stays transactional, empty prefix included.

All MySQL-behaviour tests go through the existing `SnapshotDatabase`/`DbUtil` pattern: they run for real when the `db_*` globals name a server (`phpunit-mysql.xml.dist`) and skip cleanly on SQLite-only runs. Refusal-**ordering** tests that need only a MySQL-reporting platform (e.g. empty-prefix refusal thrown before any SQL) may use a test-double connection in the house style of `ConnectionOnAnUnsupportedDatabase`. ## IMPLEMENTATION NOTES

### Step 3

- `DatabaseRestorer::refuseNamesAlreadyInUse` — decision 7(c) and 7(e) are one walk over `listTableNames()`: a reserved name whose remainder starts with this installation's prefix is collected as a leftover (presence-refusal, message lists them sorted), a reserved name that is **not** owned refuses only where the restore needs that exact name. Rejected two separate scans, because with prefix-based ownership every name the restore needs is owned by construction — the non-owned branch is the fail-closed backstop for a reserved name this installation's prefix does not account for. Invariants: an owned `_r_`/`_b_` leftover refuses whether or not this dump needs its name; a reserved table that is neither owned nor needed is left alone.
- `DatabaseRestorer::preflight` — ordered cheapest first: name length (no SQL), then the table listing, then `information_schema`. Invariant a test must hold: every refusal that needs no MySQL-only statement (empty prefix, name length, reserved name in the dump) throws before one runs, so a connection that merely *reports* MySQL reaches them on the SQLite leg.
- `DatabaseRestorer::MYSQL_NAME_LIMIT` — literal 64, not `AbstractPlatform::getMaxIdentifierLength()`, which is the un-overridden 63 for MySQL in DBAL 3.10 and would refuse names MySQL takes. Measured with `mb_strlen` over the shadow name only; both markers are three characters, so one measurement answers for both.
- `DatabaseRestorer::foldsNames` — read once per restorer from `SHOW GLOBAL VARIABLES LIKE 'lower_case_table_names'` (global because the variable has no session value; through `SHOW` because `@@…` would be rewritten by `Connection::replacePrefix`). Values 1 and 2 fold, anything else — a row that does not say included — compares as written. A test double that wants the collision or inbound-FK path without a server has to answer that query.
- `RestoreTableNames::live()` — added as the counterpart of `shadow()`/`backup()` so ownership is read off the remainder instead of a second spelling of the markers inside the restorer; `isReserved()` delegates to it, keeping both readings byte-exact and leaving folding the restorer's business.
- `DatabaseRestorer::inspect` — now also returns the dumped table names (`Inspection`), which is what the refusals are measured against; `restore()` narrows its own answer back to `tables`/`rows`, so the summary a caller gets is unchanged.
- `DatabaseRestorer::name` — the reserved-name-in-dump refusal (7f) sits in the dump reading before the prefix check, so it fires on both platforms and on an empty-prefix installation, where the prefix check alone would pass the name through.

### Step 4

- `ShadowSchema` — the rewriter is a whitelist, not a rewrite-what-you-recognise pass: a statement must be `CREATE [TEMPORARY] TABLE [IF NOT EXISTS] <t> (`, `ALTER TABLE <t> ADD …` or `CREATE [UNIQUE|FULLTEXT|SPATIAL] INDEX <i> ON <t> (`, and `<t>` must byte-equal the table whose record the DDL came from; everything else refuses. Rejected passing unrecognised statements through, because `read()` hands the dump's `ddl` list straight to `executeStatement()`, which runs a second statement behind a `;` as readily as the first. Invariants: the only table names the fill's SQL can name are `_r_` + a table the dump declared; `CREATE TABLE … LIKE`, `ALTER TABLE … RENAME`, a schema-qualified name and a stacked statement all refuse before anything runs.
- `ShadowSchema::constraint` — `_r_` + 24 hex of sha256 over a per-instance random run token, the table and the dumped constraint name (27 chars). Decision 4's example derived the token from table + name alone; that collides on the ordinary case of restoring one snapshot twice, because the first restore left its regenerated name on the live table and MySQL keeps FK/CHECK names per schema with no way to rename them. Invariants a test must hold: one instance gives the same name for the same input twice, two instances never give the same name, names are unique per (table, constraint) and well under 64.
- `ShadowSchema::statement` — only a `CONSTRAINT <name>` followed by `FOREIGN` or `CHECK` is regenerated; `CONSTRAINT <name> UNIQUE`, `PRIMARY KEY` and every index name stay as dumped, those being per-table in MySQL (decision 4). Consequence for tests: SQLite keeps index names per schema instead, so a SQLite-leg fill of a dump carrying a real secondary index collides with the live index of that name — fixtures for the fill need tables without named secondary indexes. DBAL's MySQL platform writes indexes inline in `CREATE TABLE` and emits no `CREATE INDEX` at all, so the MySQL path never meets this.
- `ShadowSchema::tokens` — comments (`--`, `#`, `/* */`) are read past as well as quoted values, and an unterminated quote or comment refuses rather than being read to the end of the statement. Rejected handling quotes only: a desynced reader's failure mode is a missed `REFERENCES`, which is a copy's foreign key left pointing at a live table — the hazard the inbound-reference refusal exists for. Invariant: every byte outside a rewritten token comes through unchanged, `DEFAULT 'pk_users'` included.
- `DatabaseRestorer::fill` — public rather than private, because `restore()` may not route MySQL through it at this commit and PHPStan level 8 reports an uncalled private method; `replace()` becomes its caller in Checklist Step 5. The dumped table names are the caller's to pass, not re-read here: the dump is read as a generator, so a foreign key can name a table that comes later in the file. Invariants: a copy is listed for cleanup before its DDL runs, so one that got halfway is dropped too; a failure leaves no `_r_` table and every live table untouched; a success leaves the copies standing for whoever swaps them in.
- `DatabaseRestorer::drop` — tries every table before reporting and names the ones that would not go in one refusal, which is what Checklist Step 6's leftover cleanup needs; `fill()` swallows that refusal so the failure that caused the cleanup is the one the caller acts on. The row-binding loop is repeated from `apply()` rather than shared, the plan keeping `apply()`/`recreate()` untouched as the SQLite apply and explicitly not unifying it with the shadow path.

### Step 5

- `DatabaseRestorer::__construct` — decision 8's "logged warning" needs a logger the class did not have, so it takes an optional `?LoggerInterface` defaulting to `NullLogger` (the pattern `Helper/Composer.php` already uses) and `app/installer/index.php` passes `$app->get('log')`. Rejected a required parameter — every construction site including the whole Snapshot suite builds `new DatabaseRestorer($connection)` — and rejected swallowing the failure. Invariant: a restore whose backup drop fails still returns its summary; the failure is a log line and never an exception.
- `DatabaseRestorer::cutOver` — the live name is read back off each copy with `RestoreTableNames::live()` instead of re-using the dump's name list, so the one statement can only rename what `fill()` reported creating, and a name that is not a copy refuses. Invariants a test must hold: exactly one `RENAME TABLE` reaches the server; `live TO _b_live` stands before `_r_live TO live` for the same table; a dumped table the installation no longer has contributes only the second half and produces no `_b_` name; whether a live counterpart exists is decided through `comparable()`, so a folding server matches one in another case and a case-sensitive one does not.
- `DatabaseRestorer::swap` — a failed cut-over drops the copies and rethrows the server's own failure; a failed backup drop after a successful rename is logged and the restore stands. Invariants: after a failed MySQL restore no `_r_`/`_b_` table exists and every live table is byte-identical; after a successful one no `_b_` table is left unless dropping it is what failed. There is no guard for an empty copy list — `end()` refuses a dump holding no tables, so `RENAME TABLE` is never built from nothing.
- `DatabaseRestorer::preflight` stays called from `restore()` rather than moving into `replace()`, deliberately: `restore()` wraps everything `replace()` throws in "Failed to restore the database from …", so a refusal moved inside would reach the panel with its own message replaced. Invariant for the refusal tests: refusal messages are never wrapped, fill and cut-over failures always are.
- `DatabaseRestorer::fill` stays public now that `replace()` calls it. It is the half that can be exercised without swapping anything, which is how the Step 4 tests reach it; nothing else in the tree calls it, and a call to it alone leaves every live table untouched.
- `DatabaseRestorer::drop` — the refusal now says "names of its own" rather than "copies", the same method dropping both the copies and the tables set aside; it keeps the words "could not be dropped" that the fill-cleanup assertion reads for.

### Step 6

- `DatabaseRestorer::acquire` — taken inside `preflight()`, after the name-length refusal and before the table listing, so the Step 3 invariant still holds (empty prefix, name length and a reserved name in the dump all refuse before one MySQL-only statement runs) while every observation the later refusals are built on is made under the lock. Rejected taking it in `restore()` around the whole call, which would have `GET_LOCK` run before a refusal that needs nothing of the server. Invariants a test must hold: a second restore is refused, not queued, while the first holds the lock; the refusal for a name too long to copy still leaves the server unasked; the lock is given up whether the restore worked, was refused after the lock, or threw.
- `DatabaseRestorer::acquire` — the lock name and the timeout are bound parameters rather than written into the statement, so `Connection::replacePrefix()` has no `@`-led text to substitute and the name never passes through SQL quoting. Anything other than `1` back from `GET_LOCK` is read as no lock, a server that will not answer included.
- `DatabaseRestorer::lockName` — `sha256` of schema and prefix, 32 hex characters behind `pagekit.restore.` (48 in all, where the server allows 64). The schema comes from `Connection::getDatabase()` rather than the `dbname` parameter, so it is the schema `information_schema` refusals are already measured against. Invariant: two restorers on the same schema and prefix lock on the same name, and a different prefix in the same schema on a different one.
- `DatabaseRestorer::clear` — suspends reference enforcement around the drop and puts the connection back on what it was, rather than being folded into the window `restore()` opens for the apply. Leftovers are a group that points at itself (copies point at each other's copies; tables a swap set aside at each other), so no order of names drops them cleanly with references enforced, and moving `restore()`'s window up to cover the preflight would run `SHOW SESSION VARIABLES LIKE 'foreign_key_checks'` before refusals that must reach an operator without the server being asked anything. Cost accepted: one extra `SHOW` on the rare restore that finds leftovers. Invariant: a leftover set with foreign keys among its members is cleared, and the connection enforces references afterwards exactly as it did before.
- `DatabaseRestorer::clear` — called from `restore()` after `preflight()` returns rather than from inside it, and last of all: it is the only thing a restore's preparation writes to the database, so a restore refused for any other reason leaves even the leftovers where they were. Its drop failure is a refusal and is therefore **not** wrapped in "Failed to restore the database from …" — same invariant as the other refusals — and it names the tables it could not remove.
- `DatabaseRestorer::refuseNamesAlreadyInUse` — now returns the owned leftovers (sorted) instead of refusing over them; the non-owned collision still throws, and it throws before anything is dropped, so a restore that is going to be refused for a foreign table in the way changes nothing.
- `DatabaseRestorer::refuseNamesAlreadyInUse` — the non-owned collision refusal stays although nothing can drive it: a name a restore needs is a dumped table behind a marker, and `name()` holds dumped tables to the installation's prefix, so the ownership branch takes every collision that can occur. Rejected deleting it — `fill()` drops the copies it noted, so a needed name that was not this installation's would have that cleanup drop a foreign table — and rejected narrowing ownership to reach it, which would leave a copy of a table the dump no longer names with nothing to clear it. Invariant a test can hold in its place: a reserved-marker table whose remainder is not under this prefix and whose name no copy needs is still standing after a restore that succeeded.
- `DatabaseRestorer::refuseInboundReferences` — a reference whose child is one of those leftovers is not a refusal: the leftover comes off in `clear()` before the first copy exists, so nothing holds it at the swap, and refusing would leave the one restore that would have removed it unable to run at all. Rejected moving `clear()` ahead of the refusals for the same effect, which would have a restore refused for something else drop tables on its way out. Invariant a test must hold: an owned `_r_`/`_b_` leftover with a foreign key into a dumped table is cleared away, while the same reference from a table that is no leftover still refuses.
- `ConnectionThatAnswersForAMysqlServer` — answers `GET_LOCK`/`RELEASE_LOCK` through `fetchOne` and records both in `asked`, `$locked` standing for a second session already holding it. The lock is the third thing only a server can say, beside folding and the reference catalogue, and without it no MySQL-double case reaches past the name-length refusal on the SQLite leg.
- Step 3 cases that read the presence-refusal as a stopping point are rewritten rather than deferred: the two length cases stop on the lock, whose message names no table, so "the refusal did not name this one" still means what it did; the leftover and ownership cases run through to the refused swap on `ConnectionThatWillNotSwapTables` and assert what the database holds afterwards; `testWhatARestoreRefusesIsPutToAnOperatorInItsOwnWords` reads the inbound-reference refusal instead. The marker-in-another-case test narrows its dump to one table — a copy of `pk_items` would be the planted `_R_pk_items` over again in the other case, and whether one database holds both is the engine's rule rather than the stand-in's.
